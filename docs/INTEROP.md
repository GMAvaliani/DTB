# DTB — контракт стыковки движков

```
модель + политика + сиды  →  траектория, экономика, журналы
```

Контракт даёт двум независимо сделанным движкам имитации деятельности общий
язык. Он не предписывает устройство движка: фиксируется только состав входа и
выхода, поэтому результаты становятся сравнимыми на одних данных и одних
сидах. Версия контракта — `1.0` (`dtb.interop.CONTRACT_VERSION`).

О разграничении предметов двух работ см. `SUBJECT_DELIMITATION.md`.

## Запрос

```json
{
  "contract_version": "1.0",
  "model": { "enterprise": { "...": "" }, "seds": {}, "...": "" },
  "scenario": { "horizon_hours": 720, "event_rate_multipliers": {} },
  "policies": [ { "id": "pol", "rule": "...", "action_ref": "..." } ],
  "seeds": [11, 12, 13],
  "options": { "trajectory_points": 60, "include_logs": true, "log_limit": 500 }
}
```

* `model` — снимок модели предприятия (`GET /api/enterprises/{id}/model`).
* `scenario` — сценарий прогона: горизонт, переопределения потоков и ресурсов,
  управляющие воздействия по времени, режим наблюдений, разогрев.
* `policies` — политики контура управления **рядом** с моделью: контур можно
  передать отдельно, не переписывая модель. Политики запроса дополняют
  (и при совпадении id перекрывают) политики модели.
* `seeds` — по одному прогону на каждый сид. Сравнение двух движков идёт по
  совпадающим сидам, поэтому это и есть общие случайные числа.
* `options` — плотность сетки траектории, включать ли журналы и их предел.

Незнакомые поля запроса адаптер **игнорирует**: контракт растёт аддитивно.

## Ответ

```json
{
  "contract_version": "1.0",
  "engine": { "name": "dtb", "version": "...", "capabilities": ["..."] },
  "runs": [
    { "seed": 11, "status": "completed",
      "trajectory": { "grid": [0, 12, 24], "kpis": {"revenue": [0, 100, 250]},
                      "stocks": {}, "pools": [[0, 0, 0]] },
      "economics": { "currency": "руб", "npv": 0, "net": 0, "by_article": {} },
      "metrics": { "switching_moments": 0, "decision_moments": 0 },
      "final_kpis": {}, "provenance": {}, "content_digest": "...",
      "logs": { "events": [], "decisions": [], "policies": [],
                "lookahead": [], "rejected_actions": [] } }
  ],
  "summary": { "runs": 1, "failed": 0 }
}
```

Обязательные поля прогона: `seed`, `status`, `trajectory`, `economics`,
`metrics`; траектории — `grid` и `kpis` (длина каждой серии равна длине
сетки); экономики — `npv`, `net`, `by_article`. Без них результат нельзя ни
сравнить, ни проверить, поэтому ответ считается нарушающим контракт.

## Возможности

Движок объявляет, что умеет: `trajectory`, `economics`, `logs`,
`control_loop`, `observations`, `calendars`, `lookahead`, `reproducible`.
Сравнение двух движков опирается на **пересечение** их возможностей, а не на
предположения о них.

## Проверка соответствия

`dtb.interop.certify(adapter, request)` прогоняет батарею:

| Проверка | Что означает |
|---|---|
| `capabilities_known` | объявлены только известные возможности |
| `responds` | движок ответил на корректный запрос |
| `schema` | ответ полон по составу полей |
| `runs_per_seed` | прогонов столько же, сколько сидов |
| `economics_numeric` | NPV каждого прогона — число |
| `reproducible` | повторный запрос с теми же сидами дал тот же результат |
| `seed_sensitive` | разные сиды дали разные траектории |

Отчёт возвращает по каждой проверке итог и пояснение. Контрактные тесты
(`tests/integration/test_interop_contract.py`) отдельно проверяют, что
нарушения **обнаруживаются**: движки с выброшенным полем, подменённым сидом,
несовместимой версией или нестабильным результатом проверку не проходят.

## Сравнение двух движков

`dtb.interop.compare_engines(left, right, request)` считает парные разности
по совпадающим сидам: по каждому KPI и по NPV — средняя разность, СКО,
95%-ДИ Стьюдента, доля прогонов «лучше»/«хуже» и признак значимости.
Поскольку сиды общие, разность очищена от общей случайности.

## API

```
GET  /api/interop/contract     описание контракта и возможностей этого движка
POST /api/interop/run          прогон по контракту для сохранённой модели
POST /api/interop/run-raw      прогон по внешнему запросу (серверная сторона)
POST /api/interop/certify      проверка движка: своего либо внешнего по URI
POST /api/interop/compare      сравнение нашего движка с внешним
```

Внешний движок задаётся как `{"uri": "...", "name": "...", "capabilities": []}`.
Список разрешённых хостов ограничивается переменной окружения
`DTB_INTEROP_HOSTS` (пусто — без ограничений, как в dev-режиме).

## Адаптеры

* `DTBEngineAdapter` — наш движок за контрактом; он же эталонная реализация,
  доказывающая, что контракт выполним и достаточен.
* `HTTPEngineAdapter` — внешний движок по URI; ответ проверяется на
  соответствие контракту **до** того, как попадёт в сравнение.
* `CallableEngineAdapter` — движок-функция в том же процессе: для тестов и
  встроенных обёрток вокруг библиотек.
