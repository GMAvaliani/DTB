# DTB — AI Architecture

Принципы (rules 5, 23):

1. **AI не заменяет математическую модель** — он помогает работать с ней.
2. **LLM — не источник истины** о состоянии предприятия. Источники истины:
   доменная модель, ERP-данные, состояние симуляции, граф знаний, конфигурация
   сценариев.
3. **LLM не меняет production-модель напрямую** — только через процедуру
   validate → preview → diff → подтверждение пользователя.

## Реализовано (rule-based, поверх структурированной модели)

`dtb.ai.AIAssistant(model, graph)`:

| Возможность | Как вычисляется |
|---|---|
| `explain_entity(node)` | связи графового окружения → утверждения («потребляет X (2)», «запускает Y», «влияет на N сущностей») |
| `search(query)` | ранжированный поиск по узлам графа |
| `find_dependencies(node)` | восходящее причинное замыкание графа |
| `analyze_deviations(forecast)` | KPI ниже плана, bottlenecks из трасс симуляции, цели с P<0.8 — только с доказательной базой |
| `suggest_missing_links()` | эвристики: потребляемая, но не производимая полезность; СЭД без цели; цель без СЭД/центра ответственности; неиспользуемый ресурс; материал без ERP-связи |
| `generate_questions()` | вопросы к модели (константные длительности, неподтверждённые интенсивности, цели без KPI, отсутствие факта) |
| `propose_change(description, mutate)` | применяет мутацию к **копии**, возвращает `ProposedChange` с diff (по `diff_snapshots`) и результатом валидации; применение — отдельное явное действие пользователя |

Всё это доступно в API (`/ai/*`, `/forecasts/deviations`) и в UI (экран
«AI-ассистент», панели объяснения в графах).

## Интерфейс LLM (подключаемый)

```python
class LLMProvider(Protocol):
    def complete(self, system: str, prompt: str) -> str: ...
```

`NullLLMProvider` — дефолт: честно сообщает, что LLM не сконфигурирован (никаких
имитаций ответов). Планируемое подключение (ROADMAP §6): Claude API-провайдер
для NL-рендеринга структурированных ответов, NL→graph-query и генерации отчётов,
где каждое утверждение снабжается ссылкой на источник (узел графа, provenance
симуляции). Контур изменения модели при этом не меняется: LLM формирует
`ProposedChange`, платформа валидирует и показывает diff, применяет только
пользователь.
