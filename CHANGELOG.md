# CHANGELOG

Формат: по фазам усиления платформы механиками референсного движка.
Правило изменений — аддитивность: ранее работавшие модели, сценарии, API и
тесты продолжают работать (ТЗ, п. 0.1 и 0.6).

## [Фаза 1] Контур управления: МП/МР, политики, наблюдения

### Добавлено

**Домен (`dtb.domain.control`)**

* `Subject` — субъект, применяющий действие: уровень полномочий, орг-единица,
  роль RBAC.
* `ControlActionDef` — управляющее действие как объект каталога модели:
  контур, эффект, цель, величина, задержка активации, разовая и повременная
  стоимость, срок, обратимость, вероятность успеха, минимальные полномочия.
  (Движок в фазе 1 применяет эффект и величину; задержка, стоимость, срок,
  вероятность и полномочия задействуются в фазах 2–3.)
* `ControlLoop` — три контура: `regulation`, `organization`, `development`.
* `Policy` и `PolicyRule` — декларативное правило выбора действия: условие,
  действие, выражение величины, приоритет, окно активности, антидребезг
  (`cooldown_hours`).
* `DecisionPoint` — момент принятия решений: `timer` (регламент),
  `event` (по виду события), `watchdog` (сторожевое условие, передний фронт).
  Флаг `requires_decision` отделяет МП, не требующие решения.
* `Observation` — наблюдаемая компонента состояния: период, задержка,
  относительная погрешность, способ оценивания (`last`, `smooth`,
  `extrapolate`), режим (`twin` или `pure_simulation`).
* `METRIC_ALIASES` — синонимы метрик наблюдения (`waiting_count` → `queue`).

**Заготовки ниши (`dtb.domain.links`, ТЗ 0.3 — интерфейсы без реализации)**

* `Link`, `Feedback` (обратный поток F←), `TransferRegistry`, `GapType`,
  `Gap` — поля и коллекции заведены, движок их не использует; валидация
  помечает их как `not_implemented`.

**Движок (`dtb.simulation`)**

* `observations.ObservationLayer` — снимки наблюдений, задержка доступности,
  шум из SHA-256-субпотока `(seed, "observation", obs_id)`, три способа
  оценивания, журнал погрешности |Y − Ŷ|.
* `decisions.DecisionScheduler` и `select_policies` — расписание МР,
  передний фронт сторожевого условия, отбор политик по приоритету.
* `engine` — МП и МР разделены: время продвигается в МП, политики вызываются
  только в МР; политика читает состояние через слой наблюдений; действие
  политики видно следующему МР (контур замкнут внутри модели). Сценарное
  действие в том же моменте уступает приоритет политике
  (`control_action_skipped`, причина `policy_priority`).
* `SimulationResult` — новые поля `decision_log`, `policy_trace`,
  `observation_error`, `rejected_actions`; метрики `decision_moments`,
  `policy_firings`, `observation_mode`.
* `Scenario.observation_mode` — переключатель `twin` / `pure_simulation` для
  всего прогона; разность итогов двух прогонов есть цена неполноты наблюдений.
* `ControlAction.action_ref` в сценарии — ссылка на действие из каталога
  модели (поле `effect` сохранено, работает как раньше).

**Схема модели**

* `EnterpriseModel.schema_version` и `migrate_snapshot()`: `SCHEMA_VERSION = 2`.
  Снимок версии 1 (без контура управления) грузится без ошибок и получает
  пустые коллекции; снимок новее поддерживаемого даёт понятную ошибку.
* Новые коллекции: `subjects`, `control_actions`, `policies`,
  `decision_points`, `observations`, `links`, `gap_types`, `gaps`.

**Хранение**

* Миграции DDL не потребовалось: модель и результат прогона хранятся как
  JSON-документы (`enterprises.model`, `model_versions.snapshot`,
  `simulations.result`). Миграция выполняется при загрузке снимка
  (`migrate_snapshot`), новые поля результата читаются через значения по
  умолчанию.
* `diff_snapshots` сравнивает и новые коллекции — изменения политик и точек
  решений видны в истории версий.

**Excel / CSV**

* Новые листы: `subjects`, `control_actions`, `policies`, `decision_points`,
  `observations` (русские имена листов распознаются: «Субъекты»,
  «Управляющие действия», «Политики», «Точки решений», «Наблюдения»).
* Компактная запись правил политики:
  `условие -> действие @ выражение величины; …` либо JSON-массив.

**API**

* CRUD для новых сущностей — через существующий маршрут
  `/enterprises/{eid}/entities/{etype}`.
* `GET /simulations/{id}/decisions` — журнал МР (триггеры, интервал).
* `GET /simulations/{id}/policy-trace[?policy_id=]` — вызовы политик, сводка
  по контурам.
* `GET /simulations/{id}/observation-error` — погрешность наблюдения.

**Валидация (гейт перед расчётом)**

* Проверки ссылок и выражений для субъектов, действий, политик, точек решений
  и наблюдений; предупреждения `policy_never_invoked`, `no_policies`,
  `insufficient_authority`, `large_observation_error`.
* Сценарий: `action_ref` должен существовать в каталоге действий.

**Граф знаний**

* Новые типы связей `DECIDES`, `OBSERVES`, `APPLIES`; анализ влияния доходит
  от точки принятия решений через политику и действие до ресурса и цели.

**Демо-модель**

* Три контура «Демо-Завода»: сверхурочная смена (регулирование, 24 ч),
  бригада второй смены (организация, 336 ч), третья линия (развитие,
  бессрочно); четыре точки принятия решений (смена, неделя, квартал, отказ
  оборудования); четыре наблюдения с задержкой и погрешностью.
* Новый сценарий `demo_pure_observation` — тот же контур при полной
  наблюдаемости; сравнение с базовым даёт цену неполноты наблюдений.
